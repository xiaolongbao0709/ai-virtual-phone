## 二、你需要在真机上亲自验收的点（我用 mock 测的部分）

1. **GitHub 查代码（P3）**：工坊右上角 GitHub 图标 → 填你自己的 owner/repo（公开仓库可不填 PAT）→ 验证 → 问「XX 功能在哪个文件实现的」。
2. **GitHub 改代码（P4）**：填一个有 `Contents: Read and write` 权限的 fine-grained PAT → 让工坊改点东西 → 看提案卡片 → 点「应用」→ 去 GitHub 看 commit → 点「撤销」验证回退。**建议先拿一个测试仓库试，别直接对主仓库。**
3. **默认是「确认后提交」模式**，全自动是 opt-in（仓库面板里切换）。

## 四、真机验收前的已知限制

- LLM 回答质量我用 DeepSeek 验的机制层，你的 key/模型下的实际问答质量需你自己感受一遍。
- 知识库语料目前是 README 浓缩 + 三份创作指南，较薄；真实高频问题需后续沉淀。
- 「开发中」弹层仍在（进工坊会弹），正式开放时删掉 `phone-qa-app.tsx` 里一个 state 即可。

## 五、架构小结（都在 lib/qa-*.ts，与小卷零重合）

```
qa-agent-engine   工具循环（文本协议）+ 流式过滤（隐藏工具指令/思考块）
qa-agent-tools    诊断4 + GitHub读3 + GitHub写1 + 反馈1，按连接状态动态启用
qa-knowledge      知识库（基础全量注入 + 专题按需）
qa-github(-write) 浏览器直连 GitHub REST，配置只存本地 kv 绝不上传
qa-chat-store     多会话 IndexedDB + 提案暂存/应用/撤销
qa-error-log      全局 + iframe 报错 ring buffer
qa-feedback       反馈单本地存储
qa-iframe-error-bridge  注入游戏/剧场 iframe 的报错捕获脚本
phone-qa-app.tsx + styles/qa.css  UI（黑灰 token 全落地）
```
